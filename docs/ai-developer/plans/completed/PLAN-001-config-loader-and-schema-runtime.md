## Problem Summary

The current codebase has 6 integration points (archetypes, schemas, routing, prompts, cleanup rules, output dirs) hardcoded in TypeScript. The generic system needs all of these to come from a `site-config.yaml` file that gets generated by the `analyse` command and can be edited by humans.

The riskiest piece is building Zod schemas dynamically from YAML definitions at runtime — this has never been tested in our codebase and determines whether we use a config-driven approach (preferred) or a code-generation approach (fallback).

## Implementation Notes

- New code goes in `src/config/` (not `lib/`) — this is the start of the new package structure
- Use `yaml` npm package for parsing (lightweight, well-maintained)
- The smartebyernorge.no config file serves as both a test fixture and a reference example
- If Phase 2 fails (Zod-from-YAML doesn't work), the fallback is code generation: `analyse` writes TypeScript files instead of YAML, and the engine imports them. Document this decision point.
